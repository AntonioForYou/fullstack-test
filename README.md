# Система комментариев с авторизацией (Fullstack CodeIgniter 4 + Docker)

Веб-приложение для публикации, просмотра и управления комментариями с полноценной системой авторизации пользователей, адаптивным интерфейсом, пагинацией, сортировкой и валидацией данных.

---

## Демо-доступ

Для быстрого входа в систему предварительно создана демонстрационная учетная запись:

| Параметр | Значение |
| --- | --- |
| **URL входа** | [http://localhost:8088/login](http://localhost:8088/login) |
| **Email** | `user@example.com` |
| **Пароль** | `User#Pass2026!` |

---

## Стек технологий

- **Backend:** PHP 8.2 (строгая типизация `declare(strict_types=1);`), CodeIgniter 4.7;
- **Database:** MySQL 8.4;
- **Frontend:** jQuery 3.7, Bootstrap 4.6, HTML5, CSS3, SVG-иконки;
- **Environment:** Docker, Docker Compose (Apache 2.4, PHP-FPM / mod_php, MySQL, Adminer);
- **Testing:** PHPUnit 9.6 (25 unit- и feature-тестов).

## Что было реализовано

### 1. Авторизация и регистрация пользователей
- **Защита маршрутов (Filters):**
  - При открытии главной страницы неавторизованные пользователи автоматически перенаправляются на страницу `/login` (`AuthFilter`).
  - Страницы входа (`/login`) и регистрации (`/register`) доступны только гостям (`GuestFilter`). Авторизованный пользователь при попытке их открыть перенаправляется на главную.
- **Страница регистрации (`/register`):**
  - Создание нового аккаунта по Email и паролю.
  - После успешной регистрации пользователь сразу авторизуется в сессии и перенаправляется к комментариям.
- **Безопасные требования к паролю:**
  - Длина не менее 8 символов;
  - Обязательное наличие строчных (`a-z`) и заглавных (`A-Z`) латинских букв;
  - Обязательное наличие цифр (`0-9`);
  - Обязательное наличие специальных символов (например, `!@#$%^&*()_+-=[]{}|;:,.<>?`);
  - Серверная валидация по регулярному выражению с выводом ошибок;
  - Подсказка по требованиям к паролю в форме регистрации.
  - Пароли хэшируются с использованием `password_hash()` (алгоритм `PASSWORD_DEFAULT` / Bcrypt).
- **Интеграция с сервисом комментариев:**
  - В шапке отображается email текущего пользователя и кнопка «Выйти» (`/logout`).
  - Из формы добавления комментария убрано ручное поле ввода Email — автоматически привязывается к почте авторизованного пользователя.

### 2. Управление комментариями (AJAX)
- **Асинхронные операции:** добавление и удаление комментариев выполняются через REST API без перезагрузки страницы.
- **Валидация формы:**
  - Проверка обязательных полей (текст комментария, дата) выполняется строго при нажатии на кнопку «Добавить комментарий».
  - На клиенте и сервере проверяется корректность формата даты (формат `ГГГГ-ММ-ДД`).
- **Сортировка:**
  - Сортировка по **ID** и по **Дате добавления**;
  - Направление сортировки: **по возрастанию (ASC)** и **по убыванию (DESC)**;
  - Элементы управления отсортированы вертикально друг под другом;
- **Постраничная навигация (пагинация):**
  - Блок пагинации размещен непосредственно под списком комментариев.
  - Рядом с номерами страниц расположен селектор количества комментариев на странице: **3, 5 или 10** комментариев.
  - Изменение лимита мгновенно пересчитывает количество страниц и отображает актуальные данные.

### 3. База данных
- **Миграции:**
  - `CreateCommentsTable`: таблица `comments` (id, name, text, date, created_at, updated_at).
  - `CreateUsersTable`: таблица `users` (id, email, password, created_at, updated_at).
- **Сидер комментариев (`CommentSeeder`):**
  - Создает демонстрационные комментарии.
- **Сидер пользователей (`UserSeeder`):**
  - Создает демонстрационную учетную запись `user@example.com` с паролем `User#Pass2026!`.

### 4. Тестирование (PHPUnit)
- Покрыты тестами модели `CommentModel` и `UserModel`, а также контроллеры `CommentController` и `AuthController`.
- Набор из 25 автоматических тестов проверяет:
  - Регистрацию с валидным паролем;
  - Отклонение регистрации при пароле короче 8 символов;
  - Отклонение регистрации при пароле без цифр, спецсимволов или нужного регистра;
  - Вход с валидными и невалидными учетными данными;
  - Завершение сессии (logout);
  - CRUD-операции, сортировку и пагинацию комментариев.

## Запуск проекта

### Обычный запуск (повседневная работа)

Чтобы запустить проект, **достаточно выполнить команду**:

```bash
docker compose up -d
```

После этого приложение сразу готово к работе:
- **Веб-приложение:** [http://localhost:8088](http://localhost:8088) (автоматически откроется страница входа)
- **Панель БД (Adminer):** [http://localhost:8080](http://localhost:8080)
- **Демо-доступ:** `user@example.com` / `User#Pass2026!`

Остановить контейнеры:
```bash
docker compose down
```
*(Все данные базы данных сохраняются в папке `db_data`).*

---

### Первоначальная инициализация

Если проект разворачивается впервые (после `git clone`):

1. **Запустить контейнеры:**
   ```bash
   docker compose up -d
   ```

2. **Установить зависимости Composer (если отсутствует папка `vendor`):**
   ```bash
   docker compose exec -u devuser web composer install
   ```

3. **Применить миграции и сидеры:**
   ```bash
   docker compose exec -u devuser web php spark migrate
   docker compose exec -u devuser web php spark db:seed UserSeeder
   docker compose exec -u devuser web php spark db:seed CommentSeeder
   ```

### Запуск тестов

Для проверки работоспособности тестов:
```bash
docker compose exec -u devuser web ./vendor/bin/phpunit
```
